# Wave 1 polish notes — apply during Tasks 2+

Task 1 (`820e8a4`) was **approved** by the code-quality reviewer. Three "Important" polish items were flagged that should be folded into Task 2's work (Task 2 modifies the same `TextPipeline` + `TextPipelineTests` surface, so it's the natural touchpoint).

## 1. Default parameter values on `TextPipeline.Input.init`
Every test currently passes all 6 fields, most as `nil`. Wave 1 has 19 more tasks — without defaults, every new field forces every call site + test to change.

Recommended init:
```swift
public init(raw: String,
            punctuationMode: PunctuationMode,
            cursorContextText: String? = nil,
            screenContextText: String? = nil,
            styleMode: TextPostProcessor.StyleMode = .none,
            glossaryWords: String? = nil)
```

## 2. Eliminate the double-call to `assemblePromptHints`
`AppDelegate.finalizeRecording` currently calls `TextPipeline.assemblePromptHints(input: makeInput(""))` once before whisper, then `TextPipeline.run(makeInput(raw))` which internally calls `assemblePromptHints` *again*. `Result.promptHints` is therefore dead at the production call site.

Two clean options:
- (a) Compute the hints once, pass them into `run(...)`, and let the call site read `Result.promptHints` from the single call.
- (b) Split `Input` into `PromptContext` (no `raw`) + `run(raw:context:styleMode:) -> Result`, eliminating the empty-string placeholder (issue #3 below).

Either is fine; (b) is cleaner if Task 2 is touching the shape anyway.

## 3. `makeInput("")` empty-string placeholder is a smell
[`AppDelegate.swift:594`] passes `""` for `raw` just to satisfy `Input.raw` when computing the prompt. Resolved automatically by option (b) above.
